Simple first, modular later

A small toolkit for clean Java boundaries.

Hive gives teams a practical convention for commands, use cases, ports, adapters, validation, and architecture tests. It helps you move quickly without turning your application into a framework project.

hive-core

Framework-free contracts

Commands, results, use cases, events, mappers, identifiers, aggregates, and port direction markers.

hive-cli

Scaffolding that compiles

Create project markers, Maven dependencies, use cases, factories, architecture tests, and standard folders.

hive-archunit

Executable architecture

Reusable ArchUnit rules for domain purity, dependency direction, ports, commands, services, and adapters.

hive-validator

Command validation flow

Use AbstractCommandFactory and SPI-based providers so use cases receive valid immutable commands.

hive-port

Optional technical ports

Clock, ID generation, event publishing, and file storage ports for application services.

hive-adapter

Lightweight defaults

Small adapter implementations for local storage, UUID generation, system clock, and in-memory events.

CLI quick start

Generate the boring parts and keep moving.

The CLI creates a Java 21 Maven project shape, source roots, config, Hive dependencies, use case files, command factories, and ArchUnit tests.

terminal 
$ mvn -pl hive-cli -am package

$ hive init
$ hive create usecase CreateUser --factory
$ hive create archtest
$ hive check

Claude Code plugin

Claude Code Quick Start

The Hive plugin lets Claude Code drive the deterministic Hive CLI instead of hand-writing architecture structure. The CLI creates the files, returns JSON with the generated paths, and Claude fills the TODO markers with real application logic before running Maven verification. This saves tokens by moving repetitive scaffolding work out of the conversation and into the CLI.

claude-code 
> /plugin marketplace add Sinapsi-Technologies/hive
> /plugin install hive@sinapsi

> /hive:new com.acme.billing

> "add a RegisterInvoice use case
 with a SaveInvoice port
 and an in-memory adapter"

/hive:new bootstraps a Hive project, runs hive init, creates a starter slice, adds an architecture test, and verifies with Maven.

hive skill activates for use cases, output ports, adapters, and modules. It runs hive create ... --json, reads the generated files, implements the TODOs, and runs mvn verify.

Token-efficient by design: Hive handles package layout, Maven dependencies, generated files, and architecture boilerplate deterministically, so Claude spends context on business logic instead of repeating structure.

Package convention

A predictable home for every boundary.

Application

Input ports and command contracts live under application.ports.in. Output capabilities live under application.ports.out. Use case implementations live in application.services.

Domain

Value objects, entities, aggregates, events, snapshots, and exceptions stay framework-free and independent from application or infrastructure code.

Infrastructure

Inbound adapters receive requests. Outbound adapters implement output ports. Configuration packages wire everything together.

Architecture rules

Let tests guard the direction of dependencies.

ArchitectureTest.java 
@AnalyzeClasses(packages = "com.example.app")
class ArchitectureTest {
    @ArchTest
    static final ArchRule hiveBaseRules =
            HexagonalRules.allBaseRules("com.example.app");
}
